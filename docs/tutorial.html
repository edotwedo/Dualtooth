Why Bluetooth Unpairs on Dual-Boot (And How to Fix It in 2026)

The definitive engineering guide to Bluetooth cryptographic link keys, BLE 5.0 Identity Resolving Keys (IRK), and syncing Linux BlueZ with Windows 11.

The Cryptographic Root Cause

When you pair a Bluetooth peripheral (like a Logitech MX Master 3S, Keychron keyboard, or AirPods), your PC and the device generate a shared 128-bit cryptographic key. The peripheral only stores one key per host MAC address.

  1. You pair the device in Windows: Windows and the mouse generate Key A.
  2. You reboot into Linux and re-pair: Linux and the mouse negotiate Key B.
  3. The mouse overwrites Key A with Key B in its non-volatile EEPROM memory.
  4. You reboot back into Windows: Windows sends authentication challenge based on Key A. The mouse rejects it.

The only permanent solution is to make both operating systems share the exact same cryptographic keys.

Why Bluetooth 5.0 LE & Modern Peripherals Fail

Older Bluetooth 2.x/3.x devices only used a single LinkKey. Modern Bluetooth 5.0+ Low Energy devices (mice, wireless earbuds, smart pens) use privacy standards with rotating resolvable MAC addresses and store:

  • [IdentityResolvingKey] (IRK): Allows Linux BlueZ to recognize the peripheral when its broadcast MAC changes.
  • [LocalSignatureKey]: Connection authentication cipher.
  • LongTermKey (LTK), EDIV, and ERand.

Legacy Python scripts (like bt-dualboot) only sync Classic link keys and corrupt or omit the IRK, which leaves modern devices unresponsive.

Method 1: Manual Terminal Sync

If you prefer doing it manually by hand:

Step 1: Pair in Linux first, then pair in Windows

Do not delete the pairing in Linux. Reboot to Windows and pair the device normally.

Step 2: Dump Windows Registry with PsExec

psexec.exe -s -i regedit

Navigate to HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\BTHPORT\Parameters\Keys\[AdapterMAC] and export the keys.

Step 3: Update BlueZ Config in Linux

sudo nano /var/lib/bluetooth/[AdapterMAC]/[DeviceMAC]/info

Paste the exact hex keys into the [IdentityResolvingKey] and [LinkKey] sections, then restart the service:

sudo systemctl restart bluetooth
